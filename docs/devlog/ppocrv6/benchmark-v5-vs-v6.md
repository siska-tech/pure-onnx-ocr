# PP-OCRv5 と PP-OCRv6 の速度比較（tract / CPU）

「PP-OCRv6 は v5 よりかなり速くなった」という主張が、このクレート（tract による CPU 推論）でどの程度成り立つかを、同じ条件で計測した。

## 要点

| 置き換え | 公式値（CPU、OpenVINO） | 本クレート（CPU、tract） | 精度（本計測の 2 画像） |
| :--- | ---: | ---: | :--- |
| v5 server → **v6 medium** | **5.2 倍速い**（7.30 s → 1.40 s） | **約 2.4 倍速い**（約 42 s → 約 17 s） | 向上 |
| v5 mobile → **v6 small** | 1.3 倍速い（0.78 s → 0.59 s） | **ほぼ同じ**（1.1 倍） | 向上 |
| v5 mobile → **v6 tiny** | 3.9 倍速い（0.78 s → 0.20 s） | **約 3.5 倍速い**（5.2 s → 1.5 s） | 中国語と英語は同程度。**日本語は読めない** |

- 速くなる方向は公式の主張と一致する。ただし倍率は、server → medium で公式の半分ほど、mobile → small ではほぼ差がなかった。
- 処理時間の大半は認識が占める（パイプライン全体の 80〜90%）。そのため、v6 の速度向上は主に認識モデルの軽量化によるものである。
- 公式値は Xeon 8350C + OpenVINO での計測で、本クレートとは推論エンジンも CPU も画像も異なる。絶対値は比較できず、比べられるのは倍率だけである。

## 公式の数値

出典: PP-OCRv6 技術レポート（arXiv 2606.13108）の Table 9「End-to-end OCR pipeline inference speed (s/image)」。

| モデル | GPU（A100、Paddle） | CPU（Xeon 8350C、OpenVINO） | Apple M4（Paddle） |
| :--- | ---: | ---: | ---: |
| PP-OCRv5 server | 0.32 | 7.30 | >10 |
| PP-OCRv5 mobile | 0.25 | 0.78 | 5.82 |
| PP-OCRv6 medium | 0.29 | 1.40 | 8.82 |
| PP-OCRv6 small | 0.25 | 0.59 | 3.07 |
| PP-OCRv6 tiny | 0.13 | 0.20 | 0.96 |

- 「5.2 倍」は CPU（OpenVINO）での v5 server → v6 medium の比較である。GPU では v5 と v6 にほとんど差がない（0.32 s → 0.29 s）。
- 同じレポートの精度は次のとおり。

  | モデル | 検出 Hmean | 認識精度 |
  | :--- | ---: | ---: |
  | v5 server | 81.6 | 78.1 |
  | v5 mobile | 75.2 | 73.7 |
  | v6 medium | 86.2 | 83.2 |
  | v6 small | 84.1 | 81.3 |
  | v6 tiny | 80.6 | 73.5 |

- Hugging Face のブログ記事とモデルカードには、速度の数値は載っていない。

## 計測方法

- 環境: Intel Core i7-1360P（P コア 4 + E コア 8、16 スレッド）、メモリ 32GB、Windows 11、AC 電源。
- 推論: tract 0.23.8 のシングルスレッド、release ビルド。
- 前処理と後処理: 本クレートの既定値を使った。検出は長辺 960px、認識は可変幅でバッチ 8、回転補正つきの切り出し。方向分類器は使っていない。
- モデル: Hugging Face 配布の ONNX。
  - `PP-OCRv5_{mobile,server}_{det,rec}_onnx`
  - `PP-OCRv6_{tiny,small,medium}_{det,rec}_onnx`
- 画像:
  - `general_ocr_002.jpg`（896x528、搭乗券、中国語と英語）
  - `ja.jpg`（1536x839、日本語の単語 57 個）
- 計測プログラム: `cargo run --release --example ocr_bench -- --runs 5 --pipeline-models v5-mobile,v6-tiny,v6-small,v6-medium`（[examples/ocr_bench.rs](../../../examples/ocr_bench.rs)）
  1. **モデル単体**: 検出は搭乗券を前処理した `[1,3,544,896]`、認識は固定の `[8,3,48,320]`。検出数の違いに左右されず、モデルそのものの速さを比べられる。
  2. **パイプライン**: `run_with_metrics_from_image` を実行する。初回（推論計画のコンパイルを含む）は別に記録し、その後 5 回の中央値を取った。
  3. 各ラウンドでモデルを順番に 1 回ずつ実行する（ラウンドロビン）。熱による CPU クロックの変動が、どのモデルにも同じように影響するようにするためである。
- v5 server はパイプライン 1 回に約 40 秒かかる。そのため、v6 medium と交互に 1 ラウンドだけ別に計測した（`--runs 1 --models v5-server,v6-medium --pipeline-models v5-server,v6-medium`）。

### 計測上の注意（Windows の電力スロットリング）

最初の計測では、v5 server のパイプラインに 1 枚あたり 270〜470 秒かかり、同じモデルでも 2〜5 倍ばらついた。

原因は Windows の電力スロットリング（EcoQoS）だった。ハイブリッド CPU では、前面にウィンドウを持たないプロセスがバックグラウンド扱いになり、E コアに低いクロックで割り当てられることがある。

対策として、`ocr_bench` は起動時に `SetProcessInformation(ProcessPowerThrottling)` を呼び、スロットリングの対象から外れるようにした。外した後は、v5 server も約 40 秒で安定した。本書の数値はすべて、スロットリングを外した後の計測である。

## 結果

### モデル単体（同一入力、ミリ秒、中央値）

| モデル | det サイズ | rec サイズ | 読み込み | 検出 `[1,3,544,896]` | 認識 `[8,3,48,320]` |
| :--- | ---: | ---: | ---: | ---: | ---: |
| v5 mobile | 4.8 MB | 16.5 MB | 65 | 345 | 732 |
| v5 server | 88.1 MB | 84.5 MB | 249 | 5,683 | 4,913 |
| v6 tiny | 1.8 MB | 4.5 MB | 27 | 270 | 154 |
| v6 small | 9.9 MB | 21.2 MB | 65 | 542 | 641 |
| v6 medium | 62.0 MB | 76.6 MB | 184 | 2,408 | 2,095 |

| 比較 | 検出 | 認識 |
| :--- | ---: | ---: |
| v6 medium / v5 server | 2.36 倍速い | 2.35 倍速い |
| v6 small / v5 mobile | **1.57 倍遅い** | 1.14 倍速い |
| v6 tiny / v5 mobile | 1.28 倍速い | 4.75 倍速い |

v6 small の検出モデルは、v5 mobile より重い（ONNX のサイズで約 2 倍）。そのぶん精度が高い。

### 精度（参考。本計測の 2 画像のみ）

精度の評価用データセットでの計測ではない。速度との兼ね合いを判断するための目安である。

| モデル | 日本語 57 語（行の完全一致） | 日本語 57 語（部分一致） | 搭乗券の主要文字列 46 個（空白を除いて部分一致） |
| :--- | ---: | ---: | ---: |
| v5 mobile | 39 | 51 | 40 |
| v5 server | 49 | 52 | 42 |
| v6 tiny | 3 | 3 | 39 |
| v6 small | 51 | 54 | 44 |
| v6 medium | **53** | **55** | 43 |

- v6 tiny が日本語を読めないのは、辞書にかながないためである（[research-ppocrv6.md](research-ppocrv6.md)）。
- 上位の世代ほど精度が高いという傾向は、公式値（v6 small ≥ v5 server）と一致する。

## 考察

1. **公式の倍率より小さい理由（server → medium の 5.2 倍に対して 2.4 倍）**
   - 公式値は OpenVINO での計測である。OpenVINO は Xeon の AVX-512 や VNNI、グラフ最適化を使い切るので、重い演算子の多い v5 server ほど遅く出る可能性がある。tract ではその差が出にくい。
   - 本クレートの既定では、検出を長辺 960px に縮小する。技術レポートの付録 B では、2048px 入力での検出の速度向上は、CPU（ONNX）で 1.30 倍にとどまっている。
   - 本計測の画像は 30〜56 行と行数が多い。認識が処理時間の大半を占めるため、パイプライン全体の倍率は、認識モデル単体の倍率（2.35 倍）に近くなる。
2. **mobile → small で速くならない理由**
   - 認識はやや速くなった（1.14 倍）が、検出は 1.57 倍遅くなっており、両者が打ち消し合っている。
   - 公式の 1.3 倍も OpenVINO の値である。tract では v6 small の検出（RepLKFPN など）の最適化が効きにくいと考えられるが、詳しい原因は調べていない。
3. **速度よりも「同じ速さで精度が上がった」ことが大きい**
   - v6 small は v5 mobile とほぼ同じ速さで、本計測では v5 server 以上の精度だった。
   - v6 tiny は v5 mobile の 3.5 倍速く、中国語と英語では同程度の精度だった。
4. **本クレートの絶対速度**
   - OpenVINO の公式値より 1 桁遅い（tiny で約 7 倍、medium で約 11 倍）。CPU とマシンの差（モバイル向けの i7-1360P と Xeon 8350C）を除いても差は大きい。主な原因は、tract がシングルスレッドで実行していることだと考えられる。
   - マルチスレッド実行（tract の executor 設定や、rayon による並列化）は、今後の速度改善の候補になる。

## 推奨

| 用途 | 推奨モデル | 理由 |
| :--- | :--- | :--- |
| 中国語と英語で、速度を最優先 | v6 tiny | v5 mobile の約 3.5 倍速く、精度は同程度 |
| 日本語を含む一般用途 | **v6 small** | v5 mobile と同じ速さで、本計測では v5 server 以上の精度 |
| 精度を最優先 | v6 medium | v5 server より約 2.4 倍速く、精度も高い |
| v5 server | 非推奨 | v6 medium より遅く、精度も低い |

## 再現手順

```bash
# モデルの配置は tests/fixtures/README.md を参照
# （PP-OCRv5 は ppocrv5/{mobile,server}_{det,rec}/ に置く）
cargo run --release --example ocr_bench -- --runs 5 \
  --pipeline-models v5-mobile,v6-tiny,v6-small,v6-medium
cargo run --release --example ocr_bench -- --runs 1 \
  --models v5-server,v6-medium --pipeline-models v5-server,v6-medium
```
