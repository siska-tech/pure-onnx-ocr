# タスク概要
これまで精度は、2 枚の画像を目で見て確認していただけだった。PaddleOCR 本体（Python 版）と同じ条件で出力を突き合わせて、検出枠と認識結果の差を定量化する。差の原因が実装の違いにある場合は修正する。

## 方法
- **参照の生成**: `scripts/paddleocr_reference.py` で PaddleOCR を実行し、出力を JSON に保存する。
  - 環境: uv の `.venv`（Python 3.12、paddleocr 3.7.0、paddlex 3.7.2、paddlepaddle 3.3.1、onnxruntime 1.30.0）。
  - 推論エンジンは `engine="onnxruntime"` とし、**本クレートと同じ ONNX ファイル**を読み込ませる。モデルの重みと推論エンジンの差をなくし、前処理・後処理の差だけを比べるためである。
  - 設定は PaddleOCR の既定値に揃える。
    - 検出: `limit_type=min, limit_side_len=64, max_side_limit=4000`
    - しきい値: thresh 0.3、box_thresh 0.6、unclip 1.5
    - 文書の前処理と、行の向きの分類は使わない。
  - 出力は `tests/reference/{model}__{image}.json`（4 モデル × 2 画像）。ファイルはコミットするので、Rust のテストは Python なしで動く。
- **比較**: `tests/paddle_parity.rs` で比較する。
  - 本クレートも同じ検出設定で実行する。
  - 検出枠は、外接矩形の IoU が 0.5 以上のものを、IoU の大きい順に 1 対 1 で対応付ける。
  - 検出の適合率・再現率・F1、対応付いた枠どうしのテキストの完全一致率、文字の類似度（1 − 正規化編集距離）を算出する。

## 見つかった差異と修正

### ① DB 後処理（`DBPostProcess.boxes_from_bitmap`）
本家の処理は次のとおりで、本クレートは「輪郭の多角形をそのまま膨張させる」という別の方法になっていた。新たに `DetPostProcessor::db_boxes` を作り、本家と同じ手順にした。

| 手順 | 本家 | 修正前の本クレート |
| :--- | :--- | :--- |
| 二値化 | `prob > thresh` | `prob >= thresh` |
| 輪郭 | `RETR_LIST`（穴も含む） | 外側の輪郭のみ |
| 候補 | 輪郭の最小面積矩形。短辺が 3px 未満なら除外 | 輪郭の多角形 |
| スコア | 矩形の内側の平均確率 | 輪郭の内側の平均確率 |
| 膨張（unclip） | **矩形**を膨張する（距離 = 面積 × 比 / 周長、角は丸め） | 輪郭の多角形を膨張する（ギザギザで周長が長くなり、膨張量が小さくなる） |
| 出力 | 膨張後の最小面積矩形。短辺が 5px 未満なら除外 | 膨張後の多角形（頂点が数百個） |
| 座標の変換 | 軸ごとに拡大縮小し、四捨五入して画像内に収める | 単一の倍率で拡大縮小する |

これにより、`OcrResult::bounding_box` は**4 頂点の矩形**になった（以前は数百頂点の多角形）。

### ② 検出入力のリサイズ（`DetResizeForTest`）
- 本家は各辺を「最も近い 32 の倍数」に**引き伸ばす**（Python の `round` なので 0.5 は偶数側に丸める。例: 528 → 512）。本クレートは 32 の倍数まで余白を**詰め物していた**（528 → 544）。
- 本家のリサイズは `cv2.resize` の bilinear で、縮小時にアンチエイリアスをかけない。本クレートは `image` の Triangle フィルタで、縮小時に平滑化していた。
- そこで `imgproc::resize_bilinear`（OpenCV の `INTER_LINEAR` 互換。ピクセル中心の基準と端の処理も同じ）を実装し、引き伸ばし方式に変更した。座標の戻しも、軸ごとの倍率（`PreprocessedDetInput::scale_xy`）で行う。
- 検出の差の大半はこれで解消した。v5 mobile の搭乗券は F1 が 0.75 から 0.985 になった。

### ③ 認識の前処理
- 切り出し:
  - 本家は `cv2.warpPerspective(INTER_CUBIC)` で、切り出しサイズは小数点以下を切り捨てる。本クレートは bilinear で、四捨五入だった。
  - bicubic と切り捨てに変更した。
- リサイズ:
  - 本家は `cv2.resize` の bilinear。本クレートは Triangle フィルタだった。
  - `resize_bilinear` に変更した。
- 入力の幅:
  - 本家の幅は `max(320, int(48 × 縦横比))`。縦横比が 320/48 を超える行は切り捨て、それ以外は切り上げる。
  - これに合わせた。
- バッチの幅を 32 の倍数に揃えるパディング（推論計画のキャッシュのため）は、本家にはない。これを外しても結果は変わらなかったので、そのまま残した。

## 影響
- 既定の検出モードは、引き続き「長辺 960」とした（速度を優先）。本家と同じ条件にしたい場合は、`det_limit_type(DetLimitType::Min).det_limit_side_len(64)` を指定する。
- 日本語 57 語での一致数（既定設定）は、v5 mobile が 39 から 42、v6 small が 51 のまま、v6 medium が 53 から 52 になった。差は計測のばらつきの範囲である。
- `OcrEngineConfig::det_polygon_scaler` を削除した。検出枠の座標変換は、本家と同じ方式に統一した。`DetPolygonScaler` 型は単体のユーティリティとして残している。
- 単体テスト 2 件を、新しい仕様に合わせて更新した。
  - 123x77 の画像は 128x64 になる（以前は 128x96）。
  - 200x32 の画像を最小辺 64 に合わせると 384x64 になる（400/32 = 12.5 を偶数側に丸める）。
